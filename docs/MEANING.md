This glossary preserves the human meaning layer around the OCEANICOS platform while keeping symbolic language separate from executable proof. The meanings below are user-provided design language; they do not establish cosmological facts, consciousness, universal authority, or external runtime availability.

## Canonical name

**Ω∞v OCEANICOS** is the human-facing name for the verification-first, local-first `omega-v-oceanicos` repository.

- **Ω — Fixpoint:** a named boundary where computation stops, evidence is weighed, and human judgment remains authoritative. In this repository, it is a design metaphor for bounded transitions, not a claim of a literal universal fixpoint.
- **∞ — Iterated continuum:** repeatable finite transitions that preserve provenance and carry verified memory forward. It does not authorize unbounded compute, autonomy, or resource use.
- **v — Verification:** the repository’s evidence discipline: attest, do not assert; distinguish observation from trust and verification.
- **OCEANICOS:** the platform body: bounded local software surfaces connected by contracts, tests, runtime observation, and human review.

## Runtime facts versus meaning

The following claims are implementation-facing and should be verified against the live repository or runtime:

- The tensor kernel computes `T[i,j,k,l] = i + j + k + l` for supported sizes `N ∈ {4, 6, 8}`.
- The API exposes `/tensor/:size` and `/api/tensor/:size` and returns explicit `UNKNOWN`, `DIVERGENT`, or `VERIFIED` states.
- The web surface renders the bounded tensor projection and digest when the local API is available.
- A SHA-256 digest establishes integrity for the exact canonical local payload; it is not a signature or deployment proof.
- Ordinary tensor reads do not append to `kai_ledger.json`; ledger mutation is a separate post-gate boundary.

Ollama, a particular local model, external credentials, distributed coordination, backup custody, deployment, and production health are optional or environment-dependent. They must remain `UNVERIFIED` until directly observed with suitable evidence.

## Governance rule

**Mirror, not master.** The software may amplify human work, health, peace, learning, and real-world care, but it does not replace human presence, consent, judgment, or responsibility. Capability is not authority; a selected upgrade is not an executed upgrade; a green local test is not proof of deployment or human impact.
